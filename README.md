# Boxmail

Boxmail 是原生 macOS AI Agent 邮件客户端，使用 SwiftUI 构建界面，通过本机 Node.js 服务连接 IMAP/SMTP 邮箱，并调用 DeepSeek Responses API 或同类兼容服务。

当前本地版本为 **0.0.12（build 13）**，对应 Git 标签 `v0.0.12`。删除恢复和取消归档会返回原文件夹，已删除提供清空确认，已发送显示数量；缓存统计明确账户和文件夹范围，滚动条统一移除轨道和边框。保留已有设置菜单、模型列表缓存、本机数据目录迁移及 PPT 理解。版本号记录在 [VERSION](VERSION)，变更见 [CHANGELOG.md](CHANGELOG.md)，完整入口见 [文档索引](docs/README.md) 与 [0.0.12 发布说明](docs/V0_0_12.md)。

界面统一使用蓝色强调、系统字体和 SF Symbols，移除次要操作描边与附件图标底框，统一邮件、摘要、整理、附件、草稿、写信和设置的排版。筛选与 AI 标签使用滑动选中反馈，面板和结果平滑展开，复制后显示成功状态，任务进度与数字变化带有动效；跟随系统“减少动态效果”偏好。摘要总览和邮件内 AI 总结共用自适应布局：宽屏分三列展示概要、待办与关键信息，中等宽度把关键信息放在概要下方，窄窗口纵向阅读；关键信息默认展开，长待办和截止时间完整换行。账号切换弹层加宽，名称与邮箱各保持单行，超长内容悬停可查看全文。邮件分栏仍可拖动，正文限制行宽。设计规则和检查记录见 [UI 调整说明](docs/UI_REVIEW.md)。

转发原文中的大批收件人会在名单内部滚动，邮件顶部也可展开完整收件人与抄送。附件预览改为“AI 理解 / 原文内容”切换，理解结果分标题、段落和列表显示；附件、发件人、模型及整理范围等下拉选框按内容宽度显示，长名称可悬停查看。系统保存面板跟随系统语言。单封 AI 任务使用流式 Responses，并保留完整的多附件上下文 JSON，连接中断时显示具体提示且保留已有结果。

## 运行项目

开发环境需要 macOS、Swift 6.0 或更高版本的工具链，以及 Node.js 24 或更高版本和 npm。项目声明的最低运行系统为 macOS 14；当前仅在 Apple Silicon、macOS 27.0.1、Swift 6.4、Node.js 24.21.0 环境验证过。

在仓库根目录运行：

```bash
./script/build_and_run.sh
```

脚本会安装缺失的后端依赖、编译 Swift 代码、生成图标、打包 Node.js 运行时和后端，并启动 `dist/Boxmail.app`。Codex 的 Run 按钮调用同一脚本。首次构建需要下载 npm 依赖；构建脚本会关闭当前运行的 Boxmail。

默认 App 使用本机临时签名，供开发验证；构建支持固定代码签名证书，尚未完成正式签名、公证和分发。`swift run` 不会准备 App 所需的后端资源，日常启动请使用上述脚本。

需要复制到另一台 Apple 芯片 Mac 测试时，执行：

```bash
./script/package_app.sh
```

脚本以 Release 配置生成 `dist/Boxmail-v0.0.12-macos-arm64-clean.zip` 及 SHA-256 校验文件，内含 App、Node.js、生产依赖和使用说明。根目录 `dist/Boxmail.app` 由日常构建脚本更新；成功构建会同步刷新 App 目录的修改时间。包内不携带开发电脑的数据或密钥，首次安装关闭演示数据、使用默认设置；不会清空任何电脑上已有的 Boxmail 配置。首次打开的系统提示及配置方法见 [另一台 Mac 测试说明](docs/TESTING_ON_ANOTHER_MAC.md)。

## 首次配置

首次启动会创建演示邮箱和示例邮件，可以直接检查界面与本机操作。演示邮箱不能发送真实邮件，示例摘要也不代表模型调用结果。

1. 打开“设置 > 账号”，添加邮箱地址、登录用户名、IMAP/SMTP 主机、端口，在下拉菜单中分别选择“SSL/TLS”或“STARTTLS”，填写邮箱授权码或服务商支持的密码。
2. 测试连接并保存账户，再执行同步；QQ、163 和企业邮箱均通过通用 IMAP/SMTP 接入，具体参数以服务商配置为准。
3. 打开“设置 > AI 助手”，填写 API 地址及 API Key，点击“刷新列表”，在模型设置中选择模型与 Low / High / Max 思考等级，测试连接后保存。默认地址为 `https://api.deepseek.com`，模型为 `deepseek-flash`，等级为 High；也可以配置兼容服务或自定义模型。刷新成功的列表立即缓存，取消设置仍保留列表，未应用的配置修改则放弃。
4. 在邮件详情中生成摘要或回复，在写信窗口检查草稿并确认发送；智能整理需确认后才应用本机分类，可撤销。

0.0.4 把单封邮件 AI 入口统一到阅读区上方：**AI 总结、翻译、附件理解、AI 回复**。译文保存在原邮件中；附件理解只处理当前邮件的附件，并结合来信内容分析。附件中心用于查找、预览和下载，可返回所属邮件。系统菜单“AI”也提供相同入口，翻译快捷键为 `Command + Shift + T`。

0.0.7 点击正文附件区的“理解本封邮件附件”，直接在当前位置批量处理全部附件。已有结果默认保留；每个附件分别显示等待、处理中、成功或失败，失败不会阻止后续文件。可只重试失败项、暂停后继续或明确重新理解全部；结果在附件区统一展开，也可复制全部。在附件预览的“AI 理解”页仍可单独理解文件。验收与限制见 [0.0.7 开发说明](docs/V0_0_7.md)。

0.0.8 总结默认用一小段概要保留核心事实、截止时间和限制条件，合并必要待办，再给出 2 至 4 条短建议。可执行的建议衔接待审核回复预览或本封附件批量理解；线下准备事项只显示提醒。旧默认提示词自动升级，自定义提示词保留；已有总结需点击“重新生成总结”才采用新的生成要求。附件结果和文件标题支持点击整行展开，Markdown 标题、列表、粗体、表格、引用及代码块共用原生样式。详情见 [0.0.8 开发说明](docs/V0_0_8.md)。

AI 回复预置**感兴趣回复、不感兴趣回复、感谢回复**，点击即生成预览，可先填写补充要求，也可切换为自定义回复。预览支持复制、关闭和重新生成，点击“使用内容”才创建可编辑草稿；再次使用同一预览会打开原草稿并保留编辑，发送仍需确认。三种态度分别表达兴趣、礼貌婉拒和确认收到，不替用户承诺参会、采购或交付。

AI 回复、总结建议中的起草、附件理解里的邮件示例及 AI 写信均要求生成正文不带签名、署名或签名占位符，保留正常称呼和事项所需的联系人、提交邮箱与日期。默认提示词会随启动升级，自定义提示词和个人签名设置保留；已有预览与草稿需重新生成后应用新规则。

智能整理可选择未分类或全部收件邮件，分析最近 10、50、100 或 200 封。任务每批 6 封在后台运行，展示进度，支持暂停、继续未完成邮件、确认应用和撤销。已完成建议会保存，超时和重启后可继续；分类确认后只修改本机标签。交互与任务规则见 [AI 功能说明](docs/AI_WORKFLOWS.md)。

AI 接口地址填写服务商的 API 基地址，服务会在其后追加 `/responses`、`/models`，解析图片时使用 `/files`。远程接口使用 HTTPS，本机模型允许回环地址 HTTP。高级参数只有思考等级 `Low / High / Max` 和超时，默认 `High`、120 秒，超时范围为 10 至 600 秒。请求不发送温度或 token 上限参数，接口依据 [DeepSeek Responses 文档](https://api-docs.deepseek.com/zh-cn/api/create-response/)。

邮箱“SSL/TLS”使用连接时直接加密的方式，常用 IMAP 端口为 993、SMTP 端口为 465；“STARTTLS”在连接后升级加密，常用端口为 143 和 587。切换安全连接时只自动调整相应的常用端口，自定义端口会保留。旧版“TLS”勾选对应新版“SSL/TLS”，已有账号无需重新添加，两种方式均验证服务器证书。

“测试连接”会分别说明 IMAP 和 SMTP 的结果。若 QQ 返回登录拒绝或 SMTP `535`，说明服务器已接收连接但未通过登录认证；先核对邮箱地址和登录用户名的完整拼写，再确认网页版 IMAP/SMTP 服务已开启、授权码由当前邮箱生成且仍有效，输入后点击“保存账户”。账号异常或登录频率限制也可能导致相同返回，不能仅凭 `535` 判定授权码错误。

摘要、回复、写信、分类、附件理解和翻译均已填写默认提示词，可自定义、恢复当前默认；清空后保存会恢复默认。客户端和后端共用 `Sources/BoxmailCore/Resources/DefaultPrompts.json`，旧设置会自动补齐默认提示词并移除旧高级参数，自定义配置会保留。

调用云端 AI 时，任务所需的邮件、附件文本或图片会发送到所配置的服务商。邮箱凭证和 API Key 保存在 macOS 钥匙串，不写入项目或邮件数据库。

钥匙串提示中应输入 Mac 登录密码并选择“始终允许”。同一次运行内复用已授权的密钥，退出时清空内存缓存；后台同步只使用本次运行已读取的邮箱凭证，未授权时在侧栏提示点击同步。临时签名在重新构建后仍可能再次询问，跨版本保留授权需固定证书，配置方法见 [钥匙串授权说明](docs/KEYCHAIN.md)。

## 附件原文件预览

附件预览默认打开“原文件预览”，不再将提取文本当作原文显示。PDF 使用 PDFKit 展示全部页面；DOCX、PPT / PPTX、图片及其他系统支持的文件使用 Quick Look；XLSX 使用本机工作簿预览，显示列宽、行高、合并单元格、字体颜色、边框和内嵌图片。提取文本仍用于搜索和 AI 理解，原附件字节不变，不会上传到在线文档预览服务。

Quick Look 对 Word 的特殊样式和分页不保证与 Word 完全一致；XLSX 预览最多显示前 10 个工作表、各表前 400 行和 60 列，超出范围会提示，复杂图表、条件格式和打印分页应使用“打开原文件”查看。PDF 加密或损坏时显示提示，可重试或在原应用中打开。实现与验收记录见 [0.0.6 开发说明](docs/V0_0_6.md)。

附件中心、邮件附件、写信和预览共用类型配色：PDF 红色、表格绿色、Word 蓝色、PPT 金色、图片紫色、文本及其他文件灰色，保持无底框图标。附件中心增加 PPT 筛选，Word 和表格筛选同时识别常见的新旧格式；图标和筛选识别不表示所有旧格式都支持 AI 文本提取。

## 从 0.0.1 升级

运行构建脚本即可启动新版，现有本机邮件、附件和草稿会保留。启动时会移除旧的温度和 token 设置，补齐思考等级及默认提示词，保留自定义提示词和已配置的服务商、模型、超时；未配置的旧默认 AI 地址和模型会改用 DeepSeek。

AI 接口已从 Chat Completions 改为 Responses。原服务商如果仅支持 `/chat/completions`，需要在“设置 > AI 助手”切换为支持 `/responses` 的服务；图片和 PDF 理解还需要 Files 接口和视觉模型。升级后可先测试连接，再使用真实邮件进行联调。

## 开发版功能和范围

| 功能 | 当前行为 |
| --- | --- |
| 邮箱接入 | 通用 IMAP/SMTP，支持多个账户和连接测试 |
| 邮件阅读与同步 | HTML 排版、图片正文、内嵌图片、常用文件夹、已读、星标、移动和本机缓存 |
| 写信与发送 | 本机草稿、回复、转发、签名、附件、发送确认和发送结果记录 |
| AI 助手 | 摘要、待办、三种态度回复预览及草稿、写信、分类建议、附件解析和翻译 |
| 邮件整理 | 分类预览、确认应用、撤销；分类标签保存在本机 |
| 附件与搜索 | 文档和图片理解，邮件、附件文本和 AI 解析结果搜索 |
| 设计参考 | Pencil MCP 导出的 19 个 HTML/CSS 页面及对应 PNG 预览 |

“已删除”中的恢复操作会返回删除前的文件夹；详情按钮和右键菜单显示目标，例如“恢复到已发送”。标题右侧的“清空”在确认后永久删除当前账户的全部已删除邮件，包括未下载的服务器邮件，不受搜索和筛选范围限制。清空真实邮箱需要连接服务器；其他账户、其他文件夹和仍被草稿引用的附件保留。旧版已删除邮件如没有来源记录，会优先依据仍保留的服务器路径，其次按发件地址识别已发送邮件，其余恢复到收件箱。

“已归档”中的“取消归档”会返回归档前的文件夹，详情提示和右键菜单显示目标；从归档删除后恢复，仍可继续取消归档。旧版邮件没有来源记录且原路径已丢失时，按发件地址识别已发送邮件，其余返回收件箱。

“已发送”侧栏显示当前账户的本机邮件数。列表底部的本机缓存数按当前账户、当前文件夹实时计算，不受搜索或筛选影响；服务器数量单独标注为上次同步结果。“设置 > 高级 > 本机数据”显示全部账户合计及各账户、文件夹明细，附件数包含邮件和本机草稿引用的文件。应用内滚动条保留浮层细滑块，移除轨道、描边和滚动区焦点边框。

图片通过 Files API 上传，再以 `input_image.file_id` 交给模型；PDF 在本机转换为页面图片，支持扫描文档，每次最多 20 页。PPT / PPTX（兼容 PPS / PPSX）通过 macOS Quick Look 和内置页面组件转换为 PDF，再复用相同的逐页 PNG 理解流程，文字、图表与内嵌图片一起提交，单附件和邮件批量理解均可使用，无需安装 Office、LibreOffice 或 OCR 服务。PPTX 的隐藏页在临时副本中展开并校验页数，原附件保持不变；旧 PPT 按系统预览可见页处理。特殊字体、动画和媒体不保证与 PowerPoint 完全一致，可先导出 PDF。DOCX、XLSX、TXT、CSV 等提交提取文本。DeepSeek 的接口支持 JPEG、PNG、GIF、WebP 图片，PDF 和 Office 文件不能直接作为文件输入，详见 [Files API](https://api-docs.deepseek.com/zh-cn/api/create-file/)。图片理解需使用支持视觉输入的模型，DeepSeek 默认使用 `deepseek-flash`。

每次同步先校准文件夹的 UID、已读和星标，再下载最多 200 封未缓存或需修复的邮件正文；历史进度随每封已完成邮件保存，后续定时同步继续补齐，也可点击列表底部“继续同步历史邮件”。列表每页 100 封，正文和附件提取文本按需加载；升级后的同步也会分批补齐旧缓存的 Reply-To 与引用头。网络恢复或电脑唤醒时会尝试同步，本次运行尚未授权钥匙串时仍需主动授权。暂未接入 IMAP IDLE 和服务器草稿同步；当前开发计划排除 Gmail、Outlook 专用接入和 OAuth。单个附件及 PDF / PPT 转换后的图片合计限制为 25 MB，提取文本最多保留 200,000 个字符，单次附件 AI 分析最多提交 60,000 字符。

HTML 邮件使用 WebKit 显示表格、文字排版和图片，CID 内嵌图片直接从邮件内容读取。默认沿用“设置 > 阅读邮件 > 屏蔽远程图片”，可在正文上方点击“加载本封邮件图片”；关闭屏蔽后自动加载外部图片。邮件脚本、表单及嵌入页面会移除，链接在系统默认浏览器中打开。旧版仅保存文本的邮件会在同步时补回 HTML，不会清空本机摘要、标签或附件。

图片上传时设置一小时过期，并在任务完成或失败后尝试删除云端临时文件；清理失败时由 DeepSeek 按过期设置处理。本机附件和解析结果会保留。

已验证 QQ 邮箱的 SSL/TLS 登录、IMAP 同步、SMTP 认证，以及招商银行和 Discord 邮件的 HTML 正文显示。已使用配置的 DeepSeek 服务验证演示邮件的整理、翻译和文本附件理解；其他邮箱服务商及其他 AI 服务仍需联调。最低系统版本、Intel Mac、正式签名和公证也尚未验证；登录启动、系统通知、本机垃圾邮件训练等能力尚未接入。

## 项目结构

```text
Sources/Boxmail/         SwiftUI 界面、状态管理、钥匙串、本机服务启动
Sources/BoxmailCore/     客户端与后端的数据模型
Sources/BoxmailPresentationRenderer/  PPT 本机逐页渲染组件
Tests/                  Swift 数据契约测试
Backend/src/            HTTP 接口、SQLite、邮件协议、AI、附件解析
Backend/test/           后端测试及本机 SMTP 集成测试
docs/                   使用、联调、版本记录及开发路线
Design/Exports/         Pencil 导出的 HTML/CSS 设计参考
预览/                   19 个页面的 PNG 预览
script/                 构建、启动、测试和图标生成脚本
.codex/environments/    Codex Run 配置
```

SwiftUI 客户端通过带会话令牌的回环 HTTP 请求访问本机服务，后端负责邮件协议、AI 调用和 SQLite 持久化。客户端启动和关闭时管理后端子进程。接口和存储说明见 [Backend/README.md](Backend/README.md)，开发及版本流程见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)。

Pencil 导出页面作为原生实现的设计参考，App 不直接运行这些 HTML。页面索引见 [页面预览](页面预览.md)；原始 `AI-Mail.pen` 位于仓库同级目录，未包含在当前 Git 基线中。

## 数据与验证

默认数据目录为 `~/Library/Application Support/Boxmail/`，其中 `boxmail.sqlite` 保存邮件、草稿、设置、AI 结果和模型列表，`attachments/` 保存附件。缓存内容未做数据库加密。升级到数据库结构版本 2 前，会在数据目录的 `backups/` 自动保存一致性 SQLite 备份；该备份不包含外置附件和钥匙串。退出 App 后再备份整个目录，包含 SQLite 的关联文件；钥匙串凭证需单独管理。应用内完整备份恢复尚待按 Roadmap 的 E1 实现。

可在“设置 > 高级 > 本机数据 > 更改位置”选择本机或已挂载本地磁盘中的空文件夹，点击“应用”或“确定”，再重新打开 App。启动时先复制 SQLite 一致性快照、附件和已有备份，更新附件路径，确认服务可用后切换位置；原目录保留。目标已有内容、目录相互包含、磁盘空间不足或文件缺失时停止迁移，继续使用原位置。自定义磁盘断开后显示重试入口，接回磁盘后继续使用，不会自动新建空邮箱。保存位置独立于邮件数据库；`BOXMAIL_DATA` 仍优先覆盖本次启动，且不会改写日常位置设置。
