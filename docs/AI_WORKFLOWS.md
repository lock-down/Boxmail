# AI 功能与交互规则

Boxmail 保留邮箱、邮件列表、阅读区三栏结构。参考本机网易邮箱大师 Mail Agent 对当前文件夹的上下文提示，把邮件任务放回当前邮件，收件箱批量分类放在智能整理页，附件批量理解放在所属邮件附件区。当前界面统一使用蓝色强调，AI 操作通过文字和图标区分；布局规则见 [UI 调整说明](UI_REVIEW.md)。

已发布行为对应本地 `v0.0.13`（build 14），包含文末的自定义分类目录；发布与验收见 [0.0.13](V0_0_13.md)。各阶段验收结果保留原日期与测试数量，当前总数及完整文档入口见 [文档索引](README.md)。

## 模型设置与列表缓存

在“设置 > AI 助手”填写 API 地址与 API Key。模型设置入口同时显示当前模型及思考等级，展开后分别进入“模型”和“思考等级”子菜单；等级为 Low / High / Max，默认 High。可以选择已有模型，也可通过“自定义模型”填写名称；空白名称不能提交。配置点击“应用”或“确定”后保存，取消则放弃未应用的修改。

“刷新列表”访问所配置服务的 `/models`，成功后按 API 地址立即缓存到本机 SQLite。关闭设置、取消设置或重启 App 均保留列表，重新打开只读取本机缓存。下次成功刷新完整替换旧列表，合法空列表清空缓存；请求失败或格式异常保留原列表。不同 API 地址分别保存，当前已选模型与自定义值仍可使用。刷新列表不会改变已选模型或思考等级；API Key 继续保存在系统钥匙串。

“测试连接”会实际请求一次模型生成，可能产生服务商费用；展开菜单和读取本机列表缓存不会调用模型。测试连接和刷新列表均使用一致的图标文字按钮。缓存与选择行为的实现及验收见 [0.0.11 记录](V0_0_11.md)。

## 功能入口

| 功能 | 入口与范围 | 结果和后续操作 |
| --- | --- | --- |
| 总结 | 当前邮件上方“AI 总结” | 精简的内容概要、待处理、您可继续，关键信息默认展开；支持更新、完整复制、勾选待办和建议衔接 |
| 翻译 | 当前邮件上方“翻译”；系统菜单 AI；Command + Shift + T | 译文保存在原邮件中，同页保留原文，可复制或重新翻译 |
| 附件理解 | 当前邮件上方“附件理解”或正文附件区 | 一键批量处理本邮件附件，结合来信分析；逐项显示进度，已有结果复用，失败可重试 |
| AI 回复 | 当前邮件上方“AI 回复” | 感兴趣、不感兴趣、感谢三种态度；先预览，使用后审核编辑，再确认发送 |
| AI 写信 | 写邮件窗口 | 按写信要求拟稿，沿用原有编辑与发送确认 |
| 摘要总览 | 左侧“AI 总结” | 查看摘要及待办，可打开对应邮件 |
| 智能整理 | 左侧“智能整理” | 按主题提出批量分类建议，确认后修改本机标签，可撤销 |
| 附件中心 | 左侧“附件中心” | 搜索、预览、下载附件；“原邮件”返回所属邮件附件区 |

单封 AI 操作在正文上方直接可见；更多菜单只保留复制正文和标记未读。结果面板标明“本封邮件”，切换邮件会切换上下文，关闭面板不会删除保存的结果。没有附件时禁用附件入口，避免进入空白页。任务失败在对应面板提示，已有结果继续可读。

附件批量理解直接显示在正文下方，不需要选择文件。上方“附件理解”定位到同一个附件区；点击“理解本封邮件附件”留在当前位置开始后台任务，每个成功结果立即保存，已有结果默认保留。单项失败继续处理后续项，可只重试失败项、暂停和继续未完成项，或明确重新理解全部。退出再打开后保留进度并显示继续入口。

结果区及文件标题支持点击整行展开，复制按钮独立，支持复制全部；点击文件卡片仍可预览原文件，在预览的“AI 理解”页可单独处理文件。理解结果统一渲染 Markdown 标题、段落、列表、表格、引用、代码块及行内强调；预览窗口以“AI 理解 / 原文件预览”切换。单个请求使用流式 Responses，收到完整且非空的结果后保存，失败会保留此前结果。批量任务依序请求本封邮件的附件，每份独立使用超时设置；不支持格式显示说明并跳过，不影响其他附件。

0.0.9 / build 10 增加 PPT / PPTX（兼容 PPS / PPSX）：在本机逐页转换为图片后，沿用 PDF 的视觉理解请求，文字、图表和内嵌图片一起提交，没有提取文字的幻灯片也可处理。最多 20 页、页面图片合计 25 MB，超限提示拆分；PPTX 隐藏页在临时副本中展开，旧 PPT 按系统预览可见页处理，原附件不变。单个文件与邮件批量任务共用此流程，损坏、取消或渲染失败保留已有分析。原文件预览继续使用系统 Quick Look，无需额外安装 Office 或在线转换服务。

## 三种态度回复

参考本机网易邮箱大师的三个回复选项及“先预览、使用内容后进入正文”的流程，保留 Boxmail 的邮件内 AI 面板。

1. 打开邮件上方的“AI 回复”，点击“感兴趣回复”“不感兴趣回复”或“感谢回复”，立即生成对应预览。
2. 可先填写补充要求，再选择态度；也可改为自定义，填写要求后生成。预置提示词追加到用户自定义回复提示词，原有设置继续生效。
3. 预览展示主题与完整正文，可复制、关闭或重新生成。每种态度保留对应结果，失败显示错误并保留旧预览；关闭当前预览不会自动展开更旧的结果。
4. 点击“使用内容”才创建本机草稿，自动填入原发件人和回复线程，并打开编辑窗口。再次使用同一预览打开原草稿，保留用户编辑。
5. 草稿可继续修改，发送仍需确认；草稿已删除或已进入发送流程时提示重新生成，避免恢复旧内容或重复发送。

感兴趣回复表达进一步了解的意愿；不感兴趣回复礼貌婉拒，不编造预算、排期等理由；感谢回复确认收到，不把感谢理解为接受或执行承诺。三种态度不替用户承诺参会、投标、采购或交付。

## AI 正文与签名

AI 回复、自定义回复、总结建议中的起草、附件理解中的回复草稿及 AI 写信只生成待审阅的正文，不在结尾添加发件人姓名、职位、公司、联系方式、发送日期或签名占位符，也不复制来信、附件及已有正文末尾的签名段。自然称呼和简短礼貌结束语可以保留；事项所需的联系人、提交邮箱、金额和截止时间仍完整保留。翻译继续忠实保留原文内容。

总结、回复、写信与附件理解的默认提示词已同步更新。启动时自动升级仍与旧默认值一致的配置，自定义提示词和已保存的个人签名保留；各撰写入口同时追加统一的无签名要求。已有预览、附件结果和草稿不会自动改写，重新生成后应用新规则。手工写信和回复原有的个人签名设置继续有效。

0.0.9 阶段使用本机模拟 AI 检查三种快捷回复、自定义提示词、总结建议、附件示例和写信请求，验证原邮件事实及个人签名设置保留；补充旧默认值迁移、自定义值保留及重复升级的验证。当时 90 项后端测试和 24 项 Swift 测试通过，未调用真实模型或发送外部邮件。

## 整理流程

1. 选择“尚未分类的收件邮件”或“全部收件邮件”，再选择最近 10、50、100 或 200 封，默认 50 封。
2. 开始后由本机服务分批处理，每批最多 6 封；客户端只查询任务进度，可继续阅读其他邮件。
3. 每批完成即保存建议，显示已分析数量。暂停会中断当前请求，保留此前已完成的结果。
4. 完成后逐封查看建议和分类依据，点击“确认应用分类”才修改标签，随后可撤销本次整理。
5. 部分失败或暂停可选择“继续未完成邮件”，使用当前 AI 设置补齐；也可先应用已完成建议。

已有建议待确认时不启动新任务，避免覆盖当前审阅内容。分类仅修改本机标签，不移动服务器邮件。界面中的分类数量反映已经应用的标签，待确认建议独立显示。

## 超时与恢复

旧实现一次提交最多 80 封邮件并等待完整响应，较大输入和 Max 思考等级会增加等待时间。新版缩小每批上下文，使用流式 Responses 接收完整结果，以后台任务保存进度。思考等级和超时继续使用用户设置；每批独立计算超时，任务总时长可以超过一次请求的时限。

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| running | 后台处理当前批次 | 阅读其他邮件、暂停 |
| needsApproval | 全部建议已完成 | 审阅、确认分类 |
| partial | 部分邮件失败，已保存成功结果 | 继续剩余邮件，或确认已有建议 |
| paused | 用户暂停或应用关闭中断 | 继续剩余邮件，或确认已有建议 |
| failed | 尚未获得有效建议 | 重试；旧版任务需重新开始 |
| applied | 建议已应用 | 撤销 |
| undone | 已恢复应用前的标签 | 开始下一次整理 |

API Key 只用于运行中的请求，不写入任务记录。重启后后台任务转为暂停，用户选择继续时重新从钥匙串获取密钥。单封任务与整理任务可同时运行，但同一账户只运行一个整理任务。

## 验证与范围

2026-10-16，59 项后端测试和 13 项 Swift 测试通过，已验证原生 App 构建、入口和演示数据流程。配置的 DeepSeek 服务在 Max 下完成 7 封虚构邮件的两批整理，约 4 秒返回全部建议；三种回复态度分别使用虚构邀请邮件验证成功，每次约 2 秒。原生演示账户也验证整理确认、撤销、译文、文本附件理解、三种回复预览、关闭和使用内容进入草稿。

回复界面验证时曾遇到一次模型返回无效 JSON，界面显示错误且未创建草稿，补充简洁要求后重试成功。预览和草稿测试均未发送外部邮件。

服务商、输入长度与网络仍会影响时长。超时后的恢复能力是正常流程的一部分，不能保证所有请求均在固定时间内完成。PDF 和图片沿用已有 Files API 和页面理解方式，本次没有增加 OCR 服务。

0.0.7 的批量附件流程使用虚构邮件及本机模拟 AI 验证，覆盖已有 3 个结果、一次处理其余 5 个附件、单项失败继续、只重试失败项、暂停、重启恢复及真实代理请求取消。完整验收记录见 [0.0.7 开发说明](V0_0_7.md)。


## 精简总结与“您可继续”

默认概要是 2 至 4 句的一小段文字，通常 100 至 220 字，简单来信更短，必要事实较多时可以更长。保留重要日期、金额、提交方式及限制，不逐一复述附件或堆砌空章节。待处理默认合并为 1 至 3 项，没有明确待办则留空；建议通常 2 至 4 条。

有操作入口的建议显示按钮和箭头：起草回复会生成待审核预览，附件建议会定位到本封附件区，需要时开始或继续批量理解。线下核算、盖章、准备材料等只显示提醒，不表示客户端能代办。复制总结包含概要、待办、建议及关键信息；新旧摘要中的关键信息均默认展开，点击标题可收起。

摘要总览和邮件内 AI 总结使用同一套布局。宽屏将概要、待办与后续操作、关键信息分为三列；中等宽度将关键信息放在概要下方；窄窗口纵向排列。长待办和截止时间按内容自然增高，展开收起保留动效；显示这些布局改动无需重新生成已有总结。

启动时升级仍使用旧默认值的总结、回复、写信及附件提示词，自定义值保留。旧总结继续可读，重新生成后才应用新提示词。0.0.8 的功能验收见 [开发说明](V0_0_8.md)，后续修正见 [变更记录](../CHANGELOG.md)。

## 0.0.13：自定义分类目录

“智能整理 > 管理分类”可新增名称和分类说明，改名或删除已有分类；所有账户共用，详情标记与列表右键菜单同步使用。AI 每次任务使用持久保存的目录快照，只接受配置中的名称，仍先预览、确认后应用，并保留撤销。分类改名同步更新邮件和整理记录，删除时邮件保留并回到未分类；目录修改需等待当前任务完成。

旧的默认分类提示词精确升级为“按本次目录选择”，自定义提示词保留。0.0.13 的会话阅读为 A1，不包含后续候选 A5 的会话 AI；其他范围与验证见 [优先功能说明](PRIORITY_WORKFLOWS.md)。
