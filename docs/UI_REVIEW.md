## 界面规则

保留系统字体和 SF Symbols，使阅读、表单、系统菜单和键盘操作维持 macOS 的使用习惯。颜色、通用按钮、空状态、页标题和内容宽度集中在 `Sources/Boxmail/Support/DesignSystem.swift`。

侧栏固定 216 pt 并贯穿窗口高度，Logo 位于窗口按钮下方，左边距 22 pt；浅蓝底写邮件入口固定在其下方，账户与导航可滚动，底部状态固定。选中项同时使用背景、文字和选中语义标识，图标、文字和行内空白均可点击。邮件列表使用完整行按钮，保留右键菜单。邮件阅读内容居中，AI 总结在较窄区域将待办与关键信息改为纵向排列。

邮件筛选占满列表可用宽度，使用 32 pt 高度和 6 pt 间隔。共用筛选以浅蓝底和蓝字表示选中，悬停、按下和细下划线焦点沿用共享控件；附件页与写信筛选维持 28 pt 紧凑高度。日期面板维持 360 pt，年月分别在弹性槽位中居中，组间距为 24 pt。

摘要中的待办与关键信息在宽屏共享可用宽度，关键信息不再固定为 200 pt。标签与值均左对齐，较窄窗口改为上下排列，完整显示长英文主题和分类说明。摘要总览的“收件箱未读”与侧栏共用同一数据来源，垃圾箱、已发送等其他文件夹的未读状态不计入。

邮件工具栏将回复按钮与其他操作分组，图标按钮和图标菜单均占 32×32 pt，组内间距固定。菜单触发器使用固定尺寸，弹出菜单按内容确定宽度，避免随阅读栏拉长。

写信正文和 AI 要求输入框使用同一个轻量 AppKit 文本组件。提示文字与光标共用字体、段落和文本容器起点；滚动条覆盖在内容边缘，仅在溢出时出现，不预留宽轨道。组件继续通过 SwiftUI Binding 保存内容，支持输入法、原生撤销及草稿自动保存。

邮件头可展开收件人与抄送，展开区域按内容增高，最多 120 pt。转发 HTML 表格中的长收件人名单最多显示 160 px，其余内容在名单内滚动；鼠标离开名单或滚到边界后继续滚动整封邮件，原始正文和地址内容不被裁切。

附件预览取消固定左右分栏，改为“AI 理解 / 原文内容”标签，内容最大宽度 900 pt。旧的中文分段结果和新的 Markdown 标题、列表共用排版组件，原文预览压缩连续空行。附件选择、整理范围、数量和发件人使用同一内容宽度菜单；模型等图标菜单固定 32 pt。长名称在菜单中缩写，完整文件名仍在详情与提示中可读。App 包声明本地化支持，系统保存面板使用系统语言，不修改系统语言偏好。

单封邮件 AI 总结、翻译、附件理解和回复继续直接显示在阅读区。附件中心仍负责搜索、预览和下载。三个回复态度、预览、使用后编辑、发送确认，以及智能整理的暂停、续跑、确认与撤销保持原流程。

设置保留七个页面、SSL/TLS 与 STARTTLS 互斥勾选、Low/High/Max 思考等级、超时及可编辑默认提示词。写信保留收件人、抄送、密送、签名、附件、本机保存与 AI 写信，不调整发送行为。

### 排版与布局

- 统一页面标题、分区标题、正文和辅助文字的字体层级，附件大小及提示文字不再使用 9 pt 字号。

- 总结的内容概要与待办在空间充足时分列，窄阅读区纵向排列；待办截止时间独立显示，建议使用轻量文本操作。关键信息与附件结果使用平铺的展开行。
- 附件中心统一图标、文件名、预览、大小和操作的对齐；卡片预览只取有界文本片段并渲染行内格式，移除 Markdown 标记，完整内容仍在预览中阅读。
- 搜索框共用一个组件；草稿、智能整理、写信侧栏和七个设置页面使用统一的留白、文字与表单样式。保留可拖动分栏、原生文本编辑与原文件预览。

### 动效规则

动效集中在有状态变化的交互，使用 SwiftUI 原生动画，不新增动画依赖。

| 交互 | 正常模式 |
| --- | --- |
| 按钮悬停与按下 | 140 ms 明暗反馈，主按钮按下轻微缩放 |
| 筛选与 AI 标签 | 220 ms 选中背景滑动，侧栏选中颜色过渡 |
| AI 面板、摘要、关键信息与附件结果 | 260 ms 平滑展开与收起，配合轻微位移和透明度，箭头同步旋转 |
| AI 任务与进度 | 处理中图标脉动，进度条与数量变化平滑过渡 |
| 待办与星标 | 状态变更使用符号反馈 |
| 复制 | 图标切换为绿色对勾，显示“已复制”，1.6 秒后恢复，重复点击重新计时 |
| 回复与写信生成结果 | 结果出现和关闭带有过渡，阅读与编辑操作保持可用 |

系统启用“减少动态效果”时，移除位移、滑动和符号弹动，保留短时颜色与状态反馈。动画参数集中在 `Sources/Boxmail/Support/UIMotion.swift`；颜色、字体和通用控件集中在 `DesignSystem.swift`。

### 账号与摘要布局反馈修正

账号切换弹层由 280 pt 加宽至 360 pt，头像和选中标记保留固定宽度，文字优先使用剩余空间。名称和邮箱地址各占一行，超长内容从中间省略，悬停可查看完整文本；侧栏入口和设置账号列表应用相同规则。

摘要总览和邮件内 AI 总结共用 `SummaryCard` 与原生 `SummaryContentLayout`，按内容区实际宽度排布：

| 内容区宽度 | 排布 |
| --- | --- |
| 至少 1120 pt 且有关键信息 | 概要、待办与后续操作、关键信息三列，完整使用可用宽度 |
| 720 至 1119 pt，或宽屏无关键信息 | 概要与待办两列，关键信息接在概要下方 |
| 小于 720 pt | 各分区纵向排列，随内容自然增高 |

关键信息默认展开，采用标签在上、值在下的排版，仍可点击标题收起；无关键信息时不保留空列。待办取消固定列宽，长标题和带日历图标的截止时间按实际宽度完整换行。展开、收起及待办反馈继续使用既有动效并适配系统降低动态偏好。

使用独立演示数据检查普通与超长账号、长概要、三条长待办、完整截止时间及六项关键信息；确认宽窗口摘要三列、邮件内两列、1150 pt 最小窗口单列，以及关键信息展开与收起。原生 App 编译、打包、启动、签名及 `git diff --check` 通过，Impeccable 布局静态扫描无报告。检查结束后恢复原邮箱，界面改动纳入本地标签 `v0.0.8`。
