# 代码优化与合并审查

本文记录 0.1.9 到 0.1.10 的代码合并、修复和保留理由。安装包的功能及验证见 [变更记录](../CHANGELOG.md#0110--2026-11-19)。

## v0.1.9 后的稳定性复核

对照 `v0.1.9` 标签与工作区，复核 Swift 客户端、后端新增服务及其调用端，检查官网副本的脚本语法与本地引用。修复集中在以下可复现的问题。

| 场景 | 修复 |
| --- | --- |
| 助手取消或确认范围 | 旧版取消时触发 SwiftUI 的 `BindingOperations.ForceUnwrapping`。范围编辑由独立草稿对象持有，关闭编辑器时绑定仍可读取该对象。取消保留会话范围和已输入的问题 |
| 收件箱滚动条 | 原生列表布局与窗口外观刷新分别重设滚动样式，复现时内容宽度在 333 与 350 pt 之间切换。列表和表格由 AppKit 管理滚动条，原生测试核对样式、滑块对象和视口宽度 |
| 来源返回与分类 | 仅复用属于当前查询的缓存页，保存查询条件和对应计数。重新分类后的邮件从旧分类移出，垃圾邮件使用常规列表加载流程 |
| 发送计划 | 旧计划不能改动同一草稿的新计划。重试前校验已确认的草稿版本，发现内容变化时可取消并重新确认 |
| 自动规则与记录 | 暂停信号只作用于该次执行。待处理的新邮件仍可触发后续规则。处理记录只展示实际存在的 AI 任务 |
| 问答来源与到期提醒 | 准备资料前记录来源，在请求模型前及保存前各核对一次。跟进改期后按当前到期时间匹配待发送提醒 |

旧版范围取消在隔离 App 复现。修复后的取消、确认及列表滚动条以原生托管视图回归验证。后端使用本机测试服务和隔离数据。完整回归结果见 [变更记录](../CHANGELOG.md)。

## 已完成的合并

| 范围 | 当前实现与维护入口 |
| --- | --- |
| 分页状态 | `PagedListStore` 共用代际票据、缓存、失败恢复；附件与分类 Store 只保留请求和筛选差异。服务端回退偏移后按当前请求保存已加载页，避免末页被标为旧页 |
| 附件预览 | `AttachmentPreviewLoader` 负责后台解码、临时文件与取消清理，`SandboxedWebPreview` 统一 WebKit 生命周期；正文和转发共用远程图片提示与检测 |
| 双端规则 | `AttachmentKinds.json`、`DiagnosticKnownFields.json` 由 Swift 和后端共读，构建同步复制到两端资源位置 |
| 后端模块 | 邮件头 SQL 与投影集中在 `message-header.js`；ZIP 汇总归入 `archive-analysis.js`，草稿匹配索引和短期读取失败状态归入 `draft-sync.js`；HTML 转义和搜索归一化复用现有入口 |
| 设置动作 | `SettingsActionState` 与 `SettingsActionFeedback` 共用进度和结果反馈；继续保留配置预览确认期间的锁定、提交重试及索引部分失败提醒 |
| 凭证暂存 | `CredentialUpdate.stage` 共用生成引用、暂存与写入失败回滚；更新、导入的空值与响应失配策略分别保留 |
| 搜索与轮询 | 回归和基准使用生产 `messagePage()`，删除旧 `Repository.search()`；运行任务共用轮询，基准等待索引 `drain()` 后核对全量搜索 |
| 原生与界面组件 | 文件面板、复制、设置字段与迁移行、错误行、刷新键、按钮、列表、排序标题及面板尺寸共用实现，规则见 [UI 规范](DESIGN.md) |
| 查询与工作区 | `MailQuery` 共用范围与条件；`WorkspaceHeader`、`MailQueryEditor` 共用标题和查询表单。跟进、规则、发送、助手及风格分别由独立 Store 和领域服务管理 |
| 后台服务 | `ApplicationServices` 组装服务，`AccountSyncCoordinator` 协调手动与 IDLE 同步，`LocalCredentials` 按当前绑定读取凭证；持久化记录不保存密钥 |
| 日期时间 | `CalendarMonthView` 共用搜索月历；`DateTimeSelection` 增加时刻、预设与时区；两处发送编辑再共用 `SendScheduleForm` |
| AI 指令与阅读 | `ai-instructions.js` 提供指令及输出结构；共享 JSON 保留双端默认值。`AnalysisDocumentView` 共用正文，表格、代码块和行内样式各自负责呈现 |
| 助手流式与滚动 | 复用 `/ai/events`，校验后保存问答；输入、历史、单轮结果分开呈现，原生编辑器处理快捷键与输入法，滚动状态区分跟随和历史阅读 |

## 后续功能的共享边界

整封理解与 AI 回复通过 `mail-ai-context.js` 共用正文和全部可读附件的原始上下文，单文件分析继续独立。准备、模型协议与结果持久化各自分层，见 [整封邮件 AI 上下文](MAIL_AI_CONTEXT.md)。

邮件头、HTML 和纯文本引用、转发预览及草稿搜索的收件信息共用 `RecipientDetailsView`。`RecipientAddressList` 只负责原生只读文本和滚动，`ScrollEventRouting` 统一按当前鼠标位置及实际可见边界分配滚轮；HTML 脚本只识别字段和报告占位位置。长名单展开为 240 pt，移到正文后立即滚动正文，无需先滚完名单。

R0 中，`OrganizationWorkspaceState` 按账户保存分类工作区状态，`ScrollPositionState` 记录与恢复滚动偏移；`AIWritingParameters` 共用写信与回复参数，`ActivityPresentation` 从已有事件生成同步历史分组。R1-R5 继续将跟进项、发送意图、规则回执和助手轮次分别持久化，不扩张单次 AI Job 的生命周期；来源迁移由 `mail-source-references.js` 集中更新。维护入口见 [R0 状态](DEVELOPMENT.md#r0-状态维护)与 [R1-R5 维护入口](DEVELOPMENT.md#工作台规则与助手的实现)。

附件中心已移除独立来源分组视图及查询分支，保留逐文件列表、来源条件和同封附件连续预览。整封理解集中在阅读区 AI 工具栏，附件区保留文件操作；回复预览和规则空态不重复主要入口。上下文菜单继续提供就近操作。

## 保留的实现边界

以下项目已完成评估，不作为必须继续合并的待办。

| 位置 | 保留原因 |
| --- | --- |
| `parser-process.js`、`parser-runner.js`、`parser-owner-watch.js` | 主进程、解析子进程和看门狗是不同隔离边界 |
| 邮件协议模块与 ZIP 各层 | 同步、文件夹、正文、恢复各有职责；ZIP 解析、缓存、AI 编排和投影持久化同样分层 |
| 附件与分类分页接口 | SQL、排序及统计范围不同；客户端共享状态机不要求合并后端查询 |
| 邮件发送与服务器草稿组装 | 发送要求有效收件人并处理引用回退；草稿允许空地址、保留 Bcc、同步 token 和独立转发快照。发送计划独立保存意图，实际提交继续调用 `sendDraft` |
| `MailStore` 主题扩展 | 导航、缓存和会话正文具有明确生命周期，仅移动文件不能减少维护规则 |
| 旧草稿缓存迁移与 `legacy-prompts.js` | 尚无停止兼容旧版本的发布约定，继续保留数据与提示词迁移 |
| 单封、会话与写信 AI 结果卡 | 预设、重生成、来源校验、结果过期和签名各有业务语义；正文共用 Markdown 排版，结果卡继续保留各自采用动作 |
| `SummaryCard` 与 `AIResultDisclosure` | 标题、计数、箭头及容器外观不同，不能仅因都有折叠头而合并 |
| PDF / Quick Look 与 Web 附件预览 | 技术栈、原生交互和访问策略不同 |
| 搜索构造与解析、引用折叠规则 | 契约两端或使用场景不同，不能按文本相似度合并 |
| 富文本样式与分页响应模型 | 双端必要校验和扁平 wire 字段各自保留，避免为少量常量引入额外加载或改变接口 |
| 基准夹具与小段 AppKit 初始化 | 继续按各场景维护，没有足够收益支持额外抽象 |

## 后续维护

- 合并同一职责和同一业务规则，保留有依据的协议、生命周期与兼容差异。
- 改动按受影响行为验证；分页要检查末页回退、请求一致性和缓存命中，不能只确认请求成功。
- 共享资源同时核对源码加载与 App 包内路径；预览和滚动检查原生界面，避免仅凭控件尺寸或测试数量判断完成。
- 当前实现归入 [开发说明](DEVELOPMENT.md)，外观规则归入 [UI 规范](DESIGN.md)，版本变化和测量口径归入 [变更记录](../CHANGELOG.md)。本地测试目录与产物不进入 Git。
