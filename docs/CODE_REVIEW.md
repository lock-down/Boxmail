# 代码优化与合并审查

截至 2026-11-13，本轮审查的高优先级合并、设置动作、凭证暂存和测试专用搜索清理均已完成，并随 0.1.9（build 48）发布。本文保留当前实现、仍需保留的边界和维护入口；移除已完成提案的旧行号、理论减量与重复验收记录。实际验证记录集中在 [CHANGELOG](../CHANGELOG.md#019--2026-11-13)。

## 已完成的合并

| 范围 | 当前实现与维护入口 |
| --- | --- |
| 分页状态 | `PagedListStore` 共用代际票据、缓存、失败恢复；附件与分类 Store 只保留请求和筛选差异。服务端回退偏移后按当前请求保存已加载页，避免末页被标为旧页 |
| 附件预览 | `AttachmentPreviewLoader` 负责后台解码、临时文件与取消清理，`SandboxedWebPreview` 统一 WebKit 生命周期；正文和转发共用远程图片提示与检测 |
| 双端规则 | `AttachmentKinds.json`、`DiagnosticKnownFields.json` 由 Swift 和后端共读，构建同步复制到两端资源位置 |
| 后端模块 | 邮件头 SQL 与投影集中在 `message-header.js`；ZIP 汇总归入 `archive-analysis.js`，草稿匹配索引和短期读取失败状态归入 `draft-sync.js`；HTML 转义和搜索归一化复用现有入口 |
| 设置动作 | `SettingsActionState` 与 `SettingsActionFeedback` 共用进度和结果反馈；继续保留配置预览确认期间的锁定、提交重试及索引部分失败提醒 |
| 凭证暂存 | `CredentialUpdate.stage` 共用生成引用、暂存与写入失败回滚；更新、导入的空值与响应失配策略分别保留 |
| 搜索与轮询 | 回归和基准使用生产 `messagePage()`，删除旧 `Repository.search()`；运行任务共用轮询，基准等待索引 `drain()` 后核对全量搜索 |
| 原生与界面组件 | 文件面板、复制、设置字段与迁移行、错误行、刷新键、按钮、列表、排序标题及面板尺寸共用实现，规则见 [UI 规范](DESIGN.md) |

## 后续功能的共享边界

整封理解与 AI 回复通过 `mail-ai-context.js` 共用正文和全部可读附件的原始上下文，单文件分析继续独立。准备、模型协议与结果持久化各自分层，见 [整封邮件 AI 上下文](MAIL_AI_CONTEXT.md)。

邮件头、HTML 和纯文本引用、转发预览及草稿搜索的收件信息共用 `RecipientDetailsView`。`RecipientAddressList` 只负责原生只读文本和滚动，`ScrollEventRouting` 统一按当前鼠标位置及实际可见边界分配滚轮；HTML 脚本只识别字段和报告占位位置。长名单展开为 240 pt，移到正文后立即滚动正文，无需先滚完名单。

## 保留的实现边界

以下项目已完成评估，不作为必须继续合并的待办。

| 位置 | 保留原因 |
| --- | --- |
| `parser-process.js`、`parser-runner.js`、`parser-owner-watch.js` | 主进程、解析子进程和看门狗是不同隔离边界 |
| 邮件协议模块与 ZIP 各层 | 同步、文件夹、正文、恢复各有职责；ZIP 解析、缓存、AI 编排和投影持久化同样分层 |
| 附件与分类分页接口 | SQL、排序及统计范围不同；客户端共享状态机不要求合并后端查询 |
| 邮件发送与服务器草稿组装 | 发送要求有效收件人并处理引用回退；草稿允许空地址、保留 Bcc、同步 token 和独立转发快照 |
| `MailStore` 主题扩展 | 导航、缓存和会话正文具有明确生命周期，仅移动文件不能减少维护规则 |
| 旧草稿缓存迁移与 `legacy-prompts.js` | 尚无停止兼容旧版本的发布约定，继续保留数据与提示词迁移 |
| 单封、会话与写信 AI 结果卡 | 预设与重生成、来源与过期校验、签名处理及排版分别不同 |
| `SummaryCard` 与 `AIResultDisclosure` | 标题、计数、箭头及容器外观不同，不能仅因都有折叠头而合并 |
| PDF / Quick Look 与 Web 附件预览 | 技术栈、原生交互和访问策略不同 |
| 搜索构造与解析、引用折叠规则 | 契约两端或使用场景不同，不能按文本相似度合并 |
| 富文本样式与分页响应模型 | 双端必要校验和扁平 wire 字段各自保留，避免为少量常量引入额外加载或改变接口 |
| 基准夹具与小段 AppKit 初始化 | 继续按各场景维护，没有足够收益支持额外抽象 |

## 后续维护

- 合并同一职责和同一业务规则，保留有依据的协议、生命周期与兼容差异。
- 改动按受影响行为验证；分页要检查末页回退、请求一致性和缓存命中，不能只确认请求成功。
- 共享资源同时核对源码加载与 App 包内路径；预览和滚动检查原生界面，避免仅凭控件尺寸或测试数量判断完成。
- 当前实现归入 [开发说明](DEVELOPMENT.md)，外观规则归入 [UI 规范](DESIGN.md)，版本变化和测量口径归入 [变更记录](../CHANGELOG.md)。本地测试目录与产物不进入 Git。
