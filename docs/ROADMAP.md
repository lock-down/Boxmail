# 开发路线

Boxmail 继续以通用 IMAP/SMTP、原生 macOS 界面和自带 API 密钥的 AI 功能为主。2026-11-16 的调研基于两个 Boxmail 账户和 Filo 2.4.8。

0.1.10 完成 R0 至 R5，0.1.11 本地版统一原生组件和图标。Gmail、Outlook 专用接入和 OAuth 暂未排期。[0.1.10 变更](../CHANGELOG.md#0110--2026-11-19) · [0.1.11 变更](../CHANGELOG.md#0111--2026-11-24)

完整证据、文档与实机差异见 [Filo 对标调研](research/FILO_BENCHMARK_2026-11-16.md)。[UI 规范](DESIGN.md)保留现行实现，R0 已同步现行源码规范，R1-R5 现行交互已另列，D6、D7 保留为未实现候选。

## 已完成的优先功能

| 编号 | 功能 | 已实现范围 |
| --- | --- | --- |
| A1 | 完整会话阅读 | 同账户按引用链归并、当前邮件置顶及倒序时间线、引用折叠、逐封操作保留原身份；预览排除签名并保留引用，本机已发送回复立即关联 |
| A2 | 联系人补全 | 本机历史和草稿、姓名与地址、键盘选择、光标片段替换及跨字段去重；空地址框的鼠标和 Tab 切换稳定，按账户查询必要字段 |
| A3 | 写信编辑增强 | 原生富文本正文、粗体、项目符号与编号列表、链接；编辑撤销、中文输入法、HTML 与纯文本发送、独立转发原文快照；字号、预设及自定颜色，列表标记随正文格式调整 |
| A4 | 服务器草稿同步 | 随邮箱或单独同步 IMAP 草稿、附件与密送；持久化 APPEND 意图、版本校验、双方编辑冲突副本、远端删除保护及 UIDVALIDITY 隔离 |
| A5 | 会话 AI | 根据同账户缓存引用链总结进展、未决事项与下一步；逐项依据跳转、上下文回复预览、最新邮件关联、过期结果拦截及已编辑草稿保护 |
| B1 | 全文索引 | 中文双字符 n-gram、正文与附件及 AI 结果、增量更新与重建；后台逐封更新，单封失败隔离，大草稿有界索引 |
| B2 | 条件搜索 | 关键词、往来对象、日期、状态、附件、账户、文件夹及分页，已支持选择全部账户搜索 |
| E1 | 完整备份恢复 | 数据库和附件快照、逐项校验、恢复前备份、跨卷复制及失败回滚；恢复后列出需重填的凭证 |
| E5 | 本机凭证文件 | 邮箱授权码与 API Key 使用 `.env`，后台读取无需钥匙串；配置与备份仅在端点、协议及身份一致时沿用本机绑定 |

A3、A4、A5 随 0.1.6 发布，0.1.7 完善富文本与地址框焦点，0.1.8 增加 ZIP 资料包、共用分页列表及原生窗口缩放，并修复草稿同步、备份和启动开销。各版细节及验证范围保留在 [变更记录](../CHANGELOG.md)，使用范围见 [使用指南](USER_GUIDE.md)。

### 0.1.9 已发布改进

- 整封理解与 AI 回复共用正文、全部可读附件和 ZIP 子项，原始资料联合提交并展示覆盖范围；独立附件分析保留。
- 收件信息共用折叠组件，长名单展开为 240 pt；名单与正文按当前鼠标位置独立滚动，覆盖 HTML 和纯文本引用、转发及草稿搜索。
- 分页状态、设置动作、凭证暂存、预览流水线及双端规则完成合并，已评估保留项见 [代码审查](CODE_REVIEW.md)。
- 文字按钮、筛选、分段选择与回复预设统一组件，集中维护尺寸、圆角、对称留白、状态与键盘焦点；原生下拉按字体高度居中。
- 附件排序表头与数据列对齐，滚动视口收缩时内容保持靠左；摘要三栏标题与关键信息反馈保持对齐，智能整理空态位于列表内部。
- 窄表格合并来源和理解状态，主要面板按当前窗口收缩并保持底栏可见；会话操作换行，长依据名称保留日期及完整提示。

这些变化保持旧邮件、草稿与 AI 结果兼容；源码验证见[本版变更](../CHANGELOG.md#019--2026-11-13)，尺寸与复用规则见 [UI 规范](DESIGN.md)。

两轮修整后，附件中心仅保留文件列表，不再单列来源邮件分组；文件行、来源限定和同封连续预览覆盖来源浏览。跨邮件比较由可见选择控件进入，保留跨页选择，开始比较时确认新范围。搜索、跟进与发送共用月历和日期时间组件；助手通过现有 SSE 通道显示部分回答，用户可选择 Return 或 Command + Return 发送。AI Markdown、默认提示词及通知设置的位置已同步现行指南。

当前实现按结构化条件预览规则，自然语言用于说明意图；自动跟进只生成可收录建议，预拟回复保留为待审阅预览。新邮件与跟进通知、角标和 IDLE 分别开启。费用在没有可核实价格时显示未知。普通发送确认后等待 10 秒提交，定时发送记录日期及原时区；备份恢复的待发计划暂停，需检查后重新安排。R5 的旧回答保留其范围和来源，采用建议仍需单独确认。

E6 正式签名、公证与更新作为分发工作独立推进；E7 缓存加密、E8 系统集成继续保留。批次内按下面的交付单元拆分，不将整批所有候选捆成一个版本。

| C1 旧结果衔接 | 历史摘要继续可读、可勾选；由用户选择哪些行动收录，保留其完成信息 | 重新生成或移除摘要不删除已收录跟进项，不覆盖用户标题、日期或完成状态；同一来源收录后可返回已有项 |
| C3 稍后处理 | 本机记录会话的处理时间和延后状态，提供查看、改期、取消及到期重新出现 | 列表菜单与阅读区均可进入时间选择；用实际日期时间说明预设，提供“已延后”视图。延后不通过服务器归档模拟 |
| C2 未回复提醒 | 为等待对方的会话设置跟进时间；同步到对方回信后解除该次等待提醒，自己的补充邮件不当作对方回复 | 取消等待提醒不等于自动完成任务。来信后显示会话更新，后续 AI 只能建议变更状态 |
| C4 通知与角标 | 分别管理新邮件提醒、跟进到期提醒和角标；启用时请求系统权限，点击定位到来源 | 权限未开时清单仍展示到期项，提供设置入口；通知与列表显示同一来源及当前状态 |

本机服务运行时处理到期事项，恢复运行时补处理；界面明确本机运行条件。未明确的期限保留原文字，由用户确认具体时间。真实回信及时性依赖 E2，界面按实际同步和处理进度反馈。

### R3：规则、记录与用量先于自动执行（0.1.10）

- D1 以“名称、适用账户、条件、动作”保存规则，支持自然语言描述意图，同时展示可理解的匹配条件或 AI 判断说明。先预览命中邮件、原因和拟执行动作，再手动运行；规则编辑不追溯修改已处理邮件。
- 第一阶段复用分类、星标、已读和归档等已有操作及整理审阅流程。规则定义、启停状态和每次执行记录独立于分类目录；记录能从结果返回来源邮件，失败项可定向重试。
- D4 按任务展示服务商、模型、次数、耗时与实际返回用量；有可靠价格时才计算费用。缺失用量和不可计算费用显示未知，取消或失败的调用也保留实际返回的消耗与状态。
- D2 在 D1 和 D4 可用后接新邮件触发；自动摘要、附件处理、跟进建议、分类与预拟回复分别启用，界面说明范围和消耗。模型结果先复用已有可用结果与任务记录，防止同一次同步重复处理。
- 自动跟进建议保留用户修改；预拟回复保留在草稿或待审阅结果，继续使用既有发送确认。先定义多条规则重叠时的动作顺序和反馈，再开放组合自动执行。

完成条件：用户能核对规则的命中与变化、暂停未来执行、找到一次处理记录并重试实际失败项；新邮件触发与手动重试不会重复改变同一处理结果。先验证用户选定的真实规则，再扩大自动处理范围。

### R4：写作偏好与发送管理（0.1.10）

- A6 在现有 AI 写信面板中加入本次输出语言与可保存风格，继续保留语气、长度和自定义要求。账户签名与写作风格分别保存，旧全局签名可继续使用。
- 选区改写先显示候选，再由用户替换原选区；继续使用现有富文本、输入法与撤销。整篇生成的采用动作明确说明替换范围，生成期间的用户编辑不能被迟到结果覆盖。
- E3 在 SMTP 提交前提供等待发送和取消入口；取消返回可编辑草稿。等待、正在提交、已发送、失败及结果不确定使用不同状态，已提交后的邮件不显示可撤销投递。
- E4 复用发送队列，支持预设与自定义日期时间、改期和取消；取消回到草稿。搜索月历由 `CalendarMonthView` 共用，`DateTimeSelection` 增加时刻和时区。退出或睡眠期间的到期计划在恢复运行后处理；离线投递失败保留记录，检查后重新安排。

完成条件：从 AI 候选到编辑、保存、撤销编辑，再到等待发送／取消／改期的路径保留正文和附件；仍沿用草稿版本、同步冲突及发送结果不确定的现有处理。发送队列不复用仅代表一次执行的 AI Job。

### R5：有依据的跨邮件助手（0.1.10）

- D5 先支持在当前邮件、会话或明确搜索范围内提问。自然语言检索先展示可编辑条件、账户和时间范围，再交给现有搜索；回答带来源邮件／附件入口和缓存覆盖说明。
- 多轮问题保留来源与范围，回答逐步显示，校验后保存。阅读当前邮件时从上下文入口打开，跨邮件问题从查询工作区打开。发送快捷键可选 Return 或 Command + Return，保留换行与输入法；在底部跟随输出，向上阅读时保持位置。
- 在查询稳定后接入已有分类、草稿和跟进动作。模型提出的动作展示对象、数量和变化，交由用户审阅，再调用已有领域服务；邮件正文不改变工具权限。
- D3 在 B7 的来源组织之后，对用户选中的不同邮件附件进行比较，说明所选文件、用户确认的关系和可读内容；不能按同名自动认定版本。引用来源，保留解析失败或未纳入的文件信息。单个 ZIP 的整体整理不算完成 D3。
- D6 的周期 AI 任务依赖调度、用量和执行记录；D7 的本地 MCP 依赖可复用查询、领域动作及明确权限，先评估只读检索，再考虑审阅后写操作。

完成条件：用户能从回答跳到证据、修改范围并重查，能审阅动作而不立即外发。跨邮件比较与整封理解共用文件准备和覆盖说明，不能分别维护两套解析规则。

## 后续实现与验收约定

- 上述未来行为不写入现行使用指南；实际交付后再更新对应指南、DESIGN 的现行章节与 CHANGELOG。调研、入口检查和模拟服务测试分别记录，不声称完成真实服务验证。
- 新功能先明确领域对象、查询和动作，再接 UI。跟进项、保存视图、规则、发送计划与 AI Job 分别有自己的生命周期；复用现有领域服务和分页组件，不把新增业务都塞进 `MailStore` 或 `runAgent`。
- 迁移保留历史摘要的待办完成状态、草稿、来源身份和用户编辑；派生视图可重建，用户确认的跟进项与发送意图独立持久化。按实际变更设计兼容验证，不增加与交付无关的假设场景或数字门槛。
- 界面变更复用现有控件和列表表面，同时检查按钮内部、列起点和整窗布局；覆盖宽窄窗口、视口收缩、长内容及嵌套面板，避免只验证控件宽度。
- 会话 AI 保持依据邮件定位、新回信后的过期提示及用户编辑保护；后续扩展须保留这些约束。
- 规则先提供预览与处理记录，再增加自动执行；复用任务持久化、暂停、确认和撤销，按消息、规则及模型配置去重。邮件内容作为数据，不得改变任务权限。
- 跟进状态由用户确认并可修改；收到对方回复取消提醒，重启补处理到期事项。
- 统一视图及搜索保持原账户和邮件身份；中文检索继续覆盖两字词、句中词、文件名及中英混排，未缓存历史明确提示。
- 同步优化覆盖千封以上回填、断网及重启、UIDVALIDITY、离线更改和账户失败隔离，再测更大数据量；退出、睡眠或离线时不承诺实时执行。
- 资源优化继续补充真实大邮箱、复杂 PDF / PPT 和长期运行测量；分别统计客户端、WebKit 与后端，区分合成负载结果与真实网络耗时。
- 撤销发送仅限 SMTP 提交前；定时任务区分等待和已执行。正式分发、加密及结构迁移均需各自的恢复与兼容验证。
