## 已实现的用户行为

| 项目 | 当前行为 |
| --- | --- |
| 历史同步 | 每个已识别文件夹先校准完整 UID、标志和数量，再从新到旧下载最多 200 封缺失或需修复正文。已完成记录逐封保存，下轮继续，可在列表底部手动继续 |
| 中断恢复 | 断网或关闭服务保留进度，重启把运行状态标为可继续；网络恢复和电脑唤醒时尝试同步。单个账号失败不阻止其他账号任务运行 |
| 列表与查找 | 每页 100 封，可追加更多；搜索在本机后端查询完整已缓存正文与附件内容。选择邮件后读取正文和附件详细结果 |
| 回复与转发 | 回复全部合并发件人或 Reply-To、原 To 和原 Cc，去重并排除当前账号自身地址；沿用原邮件所属账户，保存完整 References。转发不携带回复头 |
| 数据保护 | SQLite 版本 2 的索引迁移前生成一致性备份，不清空草稿、AI 结果或已有设置。UIDVALIDITY 改变后按同账号 Message-ID 唯一匹配重新关联数据 |
| 附件预览 | 默认打开原文件预览，可切换 AI 理解；PDF、Word 和 XLSX 使用各自的预览方式。原文件字节保持不变，未使用在线文档预览服务 |

## 原文件预览实现

- PDF：`PDFView` 直接读取原始 PDF，连续显示全部页面，可滚动、缩放和选择文本；不是将 AI 提取文本重新排版。加密或损坏文件会显示可理解的提示。
- DOCX、图片和系统支持的其他文件：`QLPreviewView` 读取私有临时文件，支持字体、嵌入图片及系统所提供的版式。关闭原生视图时显式结束 Quick Look，关闭预览窗口时清理本窗口的临时副本。
- XLSX：实测系统 Quick Look 会遗漏内嵌图片，因此使用 ExcelJS 从原工作簿读取列宽、行高、合并、字体、颜色、边框与图片锚点，在本机生成静态预览。WebKit 禁止脚本、表单和远程资源；不执行公式。
- 文件副本保持原始字节与扩展名，使用独立目录、受限权限和安全文件名；不同附件同名不会互相覆盖。系统预览通过小型 `NSViewRepresentable` 接入，SwiftUI 负责 URL、标签和加载状态。
- “打开原文件”仍交给本机默认应用，复杂格式可继续在原应用查看。提取文本继续用于搜索和 AI，不再充当原文视图。

预览范围：Word 特殊样式、字体和分页可能与 Word 不同；XLSX 最多预览前 10 个工作表、每表 400 行、60 列，超限会在预览中说明。复杂图表、条件格式、部分数字格式及打印分页应使用原应用。附件原文件仍受现有 25 MB 限制。

## 同步与接口设计

进度按账号和文件夹写入 `sync` 记录，包含 UIDVALIDITY、UID 边界、总数、已缓存数、待补齐数、状态和错误说明。每轮先完整读取元数据，读取失败不会按不完整列表删除缓存。正文只下载缺失或需修复的记录；结果不确定的 SMTP 发送继续禁止自动重试。

网页端删除或移动会在后续校准中反映。原本机附加信息先保存到 `recovery`，只有同账号中可以唯一识别的 Message-ID 才重新关联；歧义记录保留，不强行套用到其他邮件。旧 UIDVALIDITY 的待提交操作会取消并记录原因，避免改到新邮件。

`/sync` 支持后台受理，`/sync-status` 查询进度。`/messages` 返回列表分页，`/messages/:id` 返回正文；`/state?compact=1` 保留总览、计数和附件导航所需的轻量邮件索引，不携带正文或完整附件文本。原 `/state` 保留兼容行为。附件中心的搜索单独在后端查询完整文本和理解结果，列表只携带短预览片段。

当前仍会在同步时完整校准文件夹元数据，轻量状态也保留整个缓存的邮件索引。已验证千封级数据；尚未对十万封邮箱做性能承诺。IMAP IDLE、CONDSTORE 优化、FTS 全文索引、完整会话和服务器草稿同步留待后续版本。

后台同步使用本次运行已授权的钥匙串会话，未授权时需要主动点击同步。电脑睡眠、退出 App 或没有网络时不会持续接收邮件；后续恢复再补齐。

## 验证证据

执行 `./script/test.sh`，73 项后端测试与 18 项 Swift 测试通过。新增验证包括：

- 1,005 封邮件回填，在已完成 250 封后断网，再打开数据库继续；最终每封正文仅下载一次。
- 旧邮件的已读、星标和删除校准；元数据中途失败不误删缓存。
- UIDVALIDITY 变化时保留 AI 结果、附件、草稿与任务关联；旧远端操作不会误改新 UID。
- 中断同步在服务重启后显示暂停状态及原进度；后台账号失败隔离；进度和接口结果不包含凭证。
- v1 数据库迁移备份完整且不重复迁移；较新版本数据库不会被重置。
- 分页、中文正文和附件内容查询；附件中心能在不加载完整文本时找到理解结果；搜索不匹配内部 JSON 字段名。
- 回复全部、含逗号的显示名、重复地址、Reply-To、回复自己的已发送邮件，以及转发引用语义；本机 TLS SMTP 测试确认完整回复链和原有发送防重机制。
- 原始附件字节、扩展名、隔离目录和权限；工作簿合并、颜色、尺寸、内嵌图片和 HTML 转义。

原生界面使用专门生成的虚构邮件和附件验证：

- PDF 两页均可读，保留背景和图片。
- Word 显示彩色文字和内嵌图片；AI 理解与原文件来回切换可重新显示。
- XLSX 显示彩色合并标题、表格和原位置的图片。
- 追加第二页后当前阅读邮件保持不变，能选择第 193 条历史记录并加载其正文。
- 输入“历史正文专用词 1005”能找到尚未显示在列表中的第 1,005 封邮件。
- 回复全部入口生成所属账号的可编辑草稿，演示账号发送按钮保持禁用，保存后草稿计数更新。
- 最终 Release 应用的附件中心能按“预算”检索到文件名不含该词的 TXT 附件，并正确显示未加载全文附件的已解析计数。

本轮未对真实邮箱重新进行网络联调，也未向外部邮箱发送邮件或调用收费 AI。新版 QQ 与其他通用 IMAP 服务的历史回填仍需实际邮箱验证。App 构建、启动和本机签名检查已通过；测试包使用临时签名，尚未公证。

界面截图在 `artifacts/preview-v006/`，测试日志为 `artifacts/tests-v006.log`。构建产物和测试数据继续被 Git 忽略。
