# 开发、联调与版本维护

`v0.0.1` 是 Boxmail 的本地初始基线，包含原生客户端、本机后端、测试和设计导出。当前版本为 `0.0.4`，对应本地标签 `v0.0.4`，后续修改继续提交并更新版本记录。

## 修改与验证

从仓库根目录执行命令。客户端布局和操作主要位于 `Sources/Boxmail/Views/`，状态与接口调用位于 `Stores/MailStore.swift`；邮件协议和 AI 行为分别位于 `Backend/src/mail.js` 与 `agent.js`，后台整理位于 `organizer.js`。

修改接口时，一并检查 `Sources/BoxmailCore/Models.swift`、后端路由和调用方，并用测试覆盖实际的数据契约或行为变化。新增邮件发送、同步或 AI 动作时，保留发送确认、结果不确定时禁止重发、分类确认及撤销等行为。

```bash
git switch -c codex/fix-mail-sync
./script/test.sh
./script/build_and_run.sh --verify
git diff --check
git status --short
```

分支名按实际改动调整。`test.sh` 包含后端和 Swift 测试，并处理当前 Command Line Tools 的测试宏加载问题。`--verify` 只确认构建和启动，不等同于界面或服务验证；修改了界面、发送或同步行为，需要检查对应流程。调试启动可使用 `./script/build_and_run.sh --debug`。

提交前审阅 `git diff` 和暂存区，按一个可说明的问题提交，注明修改原因、验证结果及仍待确认的项目。不要提交邮箱授权码、API Key、真实邮件缓存、附件、数据库或构建产物。

## 联调检查

使用专门的测试邮箱、测试收件人和单独的后端数据目录。记录邮箱服务商、服务器参数、模型、操作步骤、预期及实际结果，错误日志去除凭证和邮件隐私内容。

| 流程 | 检查内容 |
| --- | --- |
| 账户 | 添加、测试连接、保存、重新启动、移除账户 |
| 同步 | 文件夹识别、再次同步、已读与星标、移动、网络失败后的恢复 |
| 正文 | HTML、图片邮件、CID 图片、外部图片加载、旧缓存修复及摘要附件保留 |
| 写信 | 草稿自动保存、重启恢复、附件、回复与转发、发送确认、重复点击 |
| AI | 连接测试、摘要、待办、三种回复态度、预览与关闭、使用内容、重复使用保留编辑、译文保存与切换邮件、错误就近显示 |
| 整理 | 范围、后台批次进度、暂停、部分失败、仅重试剩余、重启恢复、分类确认与撤销 |
| AI 设置 | 三档 effort、超时、自定义提示词、恢复默认、重启后的旧设置迁移 |
| 附件 | 文档文本、图片上传、扫描 PDF 页面理解、中文搜索、预览、临时文件清理及超限提示 |
| 生命周期 | 关闭和重启 App、中断任务、后端进程退出、本机数据保留 |

发送结果显示不确定时，先在服务商已发送文件夹和测试收件人邮箱确认实际投递，再决定后续处理。当前已验证 QQ 的 SSL/TLS 认证、邮件同步和正文阅读；已使用配置的 DeepSeek 服务验证虚构邮件与演示数据；真实外部发送、其他邮箱服务商及其他模型服务仍需联调。

## 钥匙串与开发签名

默认临时签名的指定要求绑定当前代码哈希，重新构建后可能需要再次授权。会话缓存减少同一进程的重复读取，后台同步在未取得缓存时显示授权提示，由用户主动点击同步。设置页仅在打开 AI 助手时读取 API Key，保存其他偏好不会清空未读取的密钥。固定签名身份的配置及验证方法见 [钥匙串授权说明](KEYCHAIN.md)。

## 版本更新

版本采用 `主版本.次版本.修订版本`。后续联调修复从 `0.0.5` 继续递增；集中新增功能可进入 `0.1.0`。每个版本都更新变更记录并建立对应 Git 标签。

以下命令以当前版本之后的 `0.0.5` 为例：

1. 把根目录 `VERSION` 改为 `0.0.5`，构建脚本会据此生成 App 版本，设置页读取 App 元数据；递增脚本中的 `CFBundleVersion`，当前构建号为 `4`。
2. 更新后端包版本和锁文件：

   ```bash
   npm version 0.0.5 --prefix Backend --no-git-tag-version
   ```

3. 在 `CHANGELOG.md` 增加版本日期、用户可见变化和验证范围，检查 README 中当前版本及功能限制是否需要调整。
4. 完成适用的测试、构建和联调，将本次修改提交后再建立版本标签：

   ```bash
   git add VERSION Backend/package.json Backend/package-lock.json CHANGELOG.md script/build_and_run.sh
   git diff --cached --check
   git commit -m "chore: release v0.0.5"
   git tag -a v0.0.5 -m "Boxmail v0.0.5"
   git status --short
   ```

功能源码和文档修改也需要审阅并纳入提交，以上暂存命令只列出了版本元数据。数据库 `user_version` 独立于 App 版本，修改数据结构前先设计迁移、备份和旧数据兼容验证。

已建立的版本标签保持不动，后续修复创建新版本。当前仅维护本地仓库；配置远程和推送由后续协作需要决定。

## 当前版本验证 · 0.0.4 · 2026-10-16

59 项后端测试和 13 项 Swift 测试通过。凭证测试覆盖会话内复用、拒绝后重试、保存失败保留原值、删除和退出清空；新增 AI 测试覆盖异步任务资源、每批范围校验、进度、取消、失败保留、重试、重启恢复、确认与撤销、SSE 分块及中断、译文保存和附件所属邮件校验。回复测试覆盖三种态度与自定义提示词合并、预览不创建草稿、失败保留结果、显式使用、重复使用保留编辑、删除或发送后拒绝恢复，以及 Swift 资源和新旧任务数据契约。原有邮件、HTML、SMTP 和 AI 参数测试继续通过。

真实服务使用已配置的 `deepseek-flash`、`effort=max`，7 封虚构邮件分两批完成，耗时约 4 秒，7 条建议全部保留。原生 App 使用演示账户验证整理完成、确认和撤销、全文翻译及结合邮件内容理解文本附件；未发送外部邮件。此结果不代表所有服务商、负载或邮件长度都不会超时，界面应始终保留恢复操作。

三种回复态度使用虚构邀请邮件验证，每种约 2 秒完成，预览阶段未创建草稿，显式使用同一结果两次只保留一份草稿。原生演示账户验证三个快捷选项、补充要求、关闭预览及使用内容打开编辑器。一次生成返回无效 JSON 后显示就近错误，重试成功；未发送外部邮件。

AI 入口设计和任务状态见 [AI 功能说明](AI_WORKFLOWS.md)。本次更新记录在 CHANGELOG 的 0.0.4 中，对应本地标签 `v0.0.4`。
