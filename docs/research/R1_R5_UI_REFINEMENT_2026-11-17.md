## 审查发现

| 位置 | 观察 |
| --- | --- |
| 助手范围 | 短字段横跨整个工作面，单项分段选择没有选择意义，表单与问题输入相距过远 |
| 规则空态 | 空白列表占满页面，指导文案放在列表外，缺少直接开始操作的入口 |
| 规则与跟进编辑 | 系统 Form、默认按钮和项目控件混用，字段、行距与提交栏不统一 |
| 附件中心 | 来源分组复选框孤立，来源、比较选择和文件操作层级不清楚 |
| 侧栏与保存视图 | 新入口增加后导航拥挤，空视图说明长期占据导航空间 |
| 图标与文案 | 新增图标缺少统一点击区域，部分页面说明使用 SMTP、持久化等实现术语 |

## 确认方向

- 产品：供日常查阅、回复和跟进邮件的原生工作台
- 性格：沉静、利落、准确
- 材质：白色信纸、浅灰工具区、现有蓝色强调
- 重点：邮件内容、附件资料与处理结果
- 标识：一致的信封来源行，连接邮件、跟进和助手依据

借鉴 Filo 的白色工作面、轻导航、清楚的操作层级与表单分组，继续使用 Boxmail 的系统字体、蓝色及原生分栏。品牌图片保持现有资源。

## 各轮调整

| 顺序 | 调整 |
| --- | --- |
| 间距 | 导航行统一 32 pt、间距 4 pt；新工作区以 20／24 pt 分组，表单字段间距 16 pt，字段标题与输入间距 8 pt |
| 颜色 | 新工作区使用白色工作面和浅灰辅助容器，蓝色用于当前选择与主操作；计数和元数据使用辅助色 |
| 图标 | 沿用 regular SF Symbols 与 32 pt 图标按钮，整理和摘要改用收件盘与正文行图标，明确文件、来源、比较与编辑的含义 |
| 文案 | 缩短页面说明和操作名，将运行条件留在相关日期面板，搜索语法按需展开，空态说明对应下一步 |
| 字体 | 新工作区标题 22 pt，行标题以 13／14 pt medium 为主，日期、数量和用量采用等宽数字 |
| 布局 | 共用紧凑标题；规则按用途分组；助手范围与提问区同宽相邻，问答范围确认后收为来源栏；跟进、规则与发送清单去除外围大框 |
| 细节 | 编辑面板复用固定提交栏；来源长标题可省略并显示完整提示；附件比较显示已选数、清除与选中反馈 |
| 内容视觉 | 资料由邮件来源表头与连续文件行呈现，保留真实文件名、类型、大小、理解状态与独立操作 |
| 动效 | 沿用 UIMotion 的选择和展开反馈，写作标题去除闪烁装饰，不新增持续动效 |

## 实现边界

`WorkspaceHeader` 负责工作区标题，`MailQueryEditor` 共用规则与助手查询字段，`SendScheduleForm` 共用两处发送时间选择。规则编辑、跟进编辑、助手范围、问答结果和附件来源组分别独立成文件。业务请求、持久化与后台服务继续留在 Store／Service。

隔离实机检查复现：已有助手会话时从附件中心开始比较，会继续显示旧搜索范围。现由 `AssistantWorkspaceStore.beginAttachmentComparison()` 开始新的范围选择，保留历史会话；修改范围期间需先确认再提问。
