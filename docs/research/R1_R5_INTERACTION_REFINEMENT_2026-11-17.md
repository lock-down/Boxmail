# R1-R5 交互与 AI 阅读修整

2026-11-17，继续处理上一轮界面精修后发现的问题。沿用 Boxmail 原生蓝灰界面与已有 Filo 调研，参考 [OpenAI 文档](https://developers.openai.com/api/docs/guides/text)的标题、正文、表格与代码分层。本轮使用 Impeccable、write 及 macOS 构建与互操作技能。

下文记录 2026-11-17 的交互调整和当轮测试。现行实现见 [开发说明](../DEVELOPMENT.md#工作台规则与助手的实现)，接口见 [后端文档](../../Backend/README.md#跟进规则发送队列与助手)。

## 结果

- 附件中心只保留文件列表，来源直接显示在文件行；删除来源分组视图、模型及查询分支。比较选择从右键菜单补充为可见控件，保留跨页选择、计数、清除与比较入口。原邮件跳转沿用统一来源服务。
- 移除附件区重复的整封理解按钮、回复预览内重复的重新生成按钮，以及规则空态与标题栏同时出现的新建规则入口。菜单中的同类操作保留为桌面上下文操作。
- 搜索、定时发送、发送管理与跟进共用 `CalendarMonthView`。日期时间选择在月历下增加时刻、快捷预设及具体日期与时区；实机确认换日期保留时刻。
- 邮件助手复用已有 SSE 通道，准备来源、等待模型和回答阶段均有反馈。部分答案可见后，来源校验通过才保存完整问答。失败时恢复待发送问题，下一轮已输入的内容继续保留。
- 输入框可选择 Return 或 Command + Return 发送，偏好持久保存。两种模式分别使用 Shift + Return、Return 换行，输入法候选确认继续交给原生文本系统。
- 对话在底部时跟随输出，向上阅读后保持位置，返回底部可继续跟随；来源按需展开。修复第一轮截图发现的跟随干扰和快捷键菜单重复箭头。
- 除邮件翻译外，AI 正文共用 Markdown 阅读组件。正文 14 pt、行距 6 pt、阅读宽度上限 760 pt；标题与连续列表使用不同间距，表格适配可用宽度并支持窄面板滚动，代码块保留空白并可单独复制。摘要展开后、回复、会话、附件、资料包与问答结果使用同一排版。
- 通过 write 重写 12 类默认提示词、3 类回复态度与共享指令。将指令和输出结构从网络服务分离；原默认值按完整文本匹配迁移，自定义值保留，原附件自定义规则继续作用于资料包。新增四类任务可在设置中编辑。
- 通知与角标归入“设置 > 常用”，实时同步放在“邮箱同步”，跟进页提供“提醒设置”跳转。设置继续统一保存和取消。修正账户签名编辑时将全局回退值误当专用签名的问题，补齐问答、比较等用量任务的中文名称。

## 原生检查

以 9 分为本轮界面完成目标，完成一次截图检查、集中修正和第二次确认。检查覆盖宽窗口、约 870 × 628 pt 的窄窗口，以及写信、设置和跟进面板；截图见本轮聊天的原生工具输出。

实际操作包括：从历史进入问答、Return 发送、切换 Command + Return、普通 Return 换行、Command + Return 发送、查看部分与完整回答、向上阅读、展开来源、打开日期时间面板、切换日期、核对附件来源与比较控件、检查规则及提示词设置。对话使用隔离演示邮件和本机模拟流式服务，生成内容明确标记为验收数据。

两轮检查后，本轮提出及观察到的界面问题均已处理。真实服务商的回答质量与长时间运行表现不由模拟输出证明。
