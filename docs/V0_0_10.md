## 自定义保存位置

“设置 > 高级 > 本机数据”显示当前完整路径、位置来源、邮件及附件数量。点击“更改位置”调用系统文件夹面板，可在本机或已挂载的本地磁盘上新建、选择一个空文件夹。

新位置先显示为待应用；点击“应用”或“确定”后保存迁移计划，下次启动生效。取消设置不会保存新选择；“取消更改”清除待迁移位置，也需要应用设置。其他设置与目录计划一起保存，选择目录本身不会打断正在执行的同步、发送或 AI 任务。

数据位置和待迁移计划以一个 JSON 配置保存在当前 App 的 macOS 偏好中，独立于邮件数据库。绝对路径的 `BOXMAIL_DATA` 对本次启动仍有最高优先级；使用此覆盖时显示来源并停用界面改址，不读取或改写日常位置计划。

## 迁移与失败处理

迁移在下次启动、启动邮件后端之前进行：

1. 原目录和目标目录分别取得排他文件锁。锁通过标准输入文件描述符传给后端，App 退出后仍由正在关闭的后端持有，直到邮件任务与 SQLite 完成关闭。
2. 检查目录可读写、目标为空、目标与源目录没有包含关系及可用空间。拒绝网络磁盘、符号链接附件和特殊文件，防止递归复制或引用目录外的数据。
3. 在目标目录内创建专属临时目录；复制附件、已有备份及其他数据文件。数据库使用 SQLite backup API 产生包含已提交 WAL 内容的一致性快照，保留结构版本、草稿、AI 结果、任务及待同步操作，并进行 `quick_check`。
4. 核对每条附件记录指向源目录内的实际文件，按新目录重写副本的绝对路径。原数据库业务记录和附件不作修改；SQLite 可在原目录恢复或准备 WAL 辅助文件，兼容正常关闭后没有 `-wal` / `-shm` 的数据库。
5. 复查目标无新增文件，再发布准备完成的副本。目标后端健康检查通过后，才保存新位置；原目录继续保留，用户核对后自行处理。

迁移出错时清理本次尚未完成的副本，清除失败的迁移计划并继续使用原位置，显示具体原因。服务验证失败或进程意外退出后，可能保留目标中的完整或部分副本；它们不会自动覆盖，重新迁移需选择另一个空文件夹。此流程不等同于完整的备份恢复或两目录合并。

已保存的自定义目录缺失、数据库丢失或外置盘未接入时，显示启动失败原因、“重试”和“打开数据设置”，不会在原路径重新建立空数据库。重新接入磁盘后可重试。多个由 App 启动的实例不能同时写入同一目录；独立后端联调继续使用专门的数据目录。

## 本轮范围
