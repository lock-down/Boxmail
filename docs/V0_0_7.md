## 使用行为

- 默认保留已有理解结果，按邮件附件顺序处理其余文件。8 个附件中已有 3 个结果时，一次点击自动处理其余 5 个。
- 每个文件显示等待、正在理解、成功、失败或暂不支持，进度和当前文件名在附件区展示。可以继续阅读其他邮件。
- 每个成功结果立即保存；某个文件失败后继续后续文件。重试仅请求失败或未完成项，成功项不再调用 AI。
- 支持暂停和继续，应用关闭中断后恢复为暂停；“重新理解全部”明确重新处理全部支持的附件。失败保留原有结果。
- 附件区可按文件展开理解结果、复制全部。文件卡片仍打开原文件预览，“AI 理解”页保留单文件操作。

## 实现与边界

本机服务增加 `AttachmentBatch` 管理器与 `POST /messages/:id/attachments/analyze`。请求立即返回任务 ID，客户端通过任务接口查询进度，不把所有附件串成一个等待时间过长的 HTTP 请求。每个附件依序使用原有代理、当前邮件上下文和已配置的 AI 提示词、模型、超时。

任务记录只保存邮件关联、各附件状态和错误；API Key 仅存在运行请求中。入队与实际执行前验证所属邮件和账号，处理时不允许移除该账号或同时单独重写同封附件。重复点击复用现有运行任务，重试保留原范围；新建任务重新确定附件范围。

不支持格式标为跳过；解析损坏、模型拒绝、PDF 超过 20 页等按单项错误或不支持提示呈现，可处理文件后重试。DOCX 和 XLSX 的 AI 输入沿用提取文本，PDF 和图片沿用页面图片及 Files API；原文件预览与理解输入分别处理。每个请求独立使用超时，整个批量任务可能持续更久。退出 App 后任务不会继续运行。

## 验证

执行 `./script/test.sh`：82 项后端测试与 19 项 Swift 测试通过。本次新增 9 项后端测试、1 项 Swift 契约测试，覆盖：

- 8 个附件顺序处理、3 个已有结果复用、重复点击不重复入队，任务不包含 API Key。
- 单项超时后继续、只重试失败项、明确重新分析时失败保留旧结果。
- 不支持格式、缺失文件、跨邮件附件、跨账号输入及入队后文件关联变化。
- 暂停、关闭取消请求、重启恢复与成功进度保留；禁止删除运行中的账号与冲突单文件操作。
- 真实附件代理连接本机模拟 Responses 服务，逐份携带邮件上下文；空白结果不写入，取消 HTTP 请求不保存残缺结果。
- Swift 新旧任务兼容解码、逐项状态、错误及序列化往返。

原生 UI 使用独立的验收副本、虚构 DOCX/XLSX 邮件、本机模拟 AI；验收副本隔离钥匙串服务名，未读取真实凭证。验证点击后仍停留附件区、各项自动处理、切换邮件时任务继续、7/8 成功及失败说明、只重试剩余 1 项并达到 8/8、结果展开和复制入口。截图保存在 `artifacts/preview-v007/`，模拟请求日志在 `artifacts/qa-v007-data/qa-calls.jsonl`。
