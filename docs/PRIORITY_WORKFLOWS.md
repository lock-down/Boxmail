# 优先功能：分类、会话、联系人、搜索与备份

日期：2026-10-21。本文对应 **0.0.13（build 14）**，在 0.0.12 基础上完成并归档于本地标签 `v0.0.13`，发布产物见 [0.0.13 说明](V0_0_13.md)。对应 [Roadmap](GITHUB_RESEARCH_AND_ROADMAP.md) 的 E1、A1、A2、B1、B2，并增加用户要求的自定义分类标签。

## 使用入口

| 功能 | 入口与行为 |
| --- | --- |
| 自定义分类 | 智能整理右上角“管理分类”，左侧选择分类，右侧新增、编辑说明或删除；详情标记和列表右键菜单共用同一目录 |
| 完整会话 | 打开有引用关系的邮件后，阅读区按时间列出本账户已缓存的往来，逐封展开、回复或打开原邮件 |
| 联系人补全 | 写信中的收件人、抄送和密送，输入姓名或邮箱后显示本机建议，上下键选择、回车或 Tab 填入、Esc 关闭 |
| 条件搜索 | 顶部搜索框旁的条件按钮；也可直接输入带条件的查询 |
| 全文索引 | 搜索时自动更新；“设置 > 高级 > 本机搜索索引”可检查数量并重建 |
| 完整备份恢复 | “设置 > 高级 > 完整备份与恢复”，通过系统文件面板保存或选择 ZIP |

## 自定义分类

管理面板以左侧目录、右侧编辑分栏展示。点击“新增”填写名称和多行说明，保存后自动定位到该分类；编辑区显示字符数，超过长度时不能保存。搜索与整理范围、发件账户、设置加密方式共用带选中标记的原生菜单，长值可省略显示并通过悬停查看。

分类目录供所有账户共用。名称为 1 至 32 个字符、不可重复；说明最多 500 个字符，可描述哪些来信应进入该分类。最多保存 100 项；“未分类”为固定接收位置，不可改名或删除。原有六类在首次升级时作为初始目录，已有的其他本机分类也会保留；删除原有分类后，重启不会重新添加。

智能整理在启动任务时保存所用分类名称和说明，模型只可从该目录选择。分类建议继续先预览、再确认应用；未返回有效分类的邮件可继续补齐。改名同步更新邮件、恢复记录和整理记录，删除时相关邮件归为未分类，邮件本身保留。目录变更需等待同步或 AI 任务完成，以免运行中的任务使用过期配置。已有自定义提示词保留，只升级与旧默认值完全一致的分类提示词。

## A1：会话阅读

按同账户中的 Message-ID、In-Reply-To、References 建立引用关系，缺失父邮件时仍可通过共同引用归并；不按主题相同直接合并，也不跨账户合并。每封邮件保留独立 ID、账户、日期和文件夹。原列表选中的邮件标为“当前邮件”，顶部操作仍针对它；其他邮件提供明确的“回复此封”“打开此封邮件”及归档或恢复操作。

会话按时间排列，每次载入 100 封，可继续加载。正文与附件在展开后按需读取；常见纯文本回复头、`>` 引用和 HTML blockquote / Gmail / Yahoo 引用默认折叠，可以展开完整内容。折叠只影响阅读，不改写原文及回复引用链。尚未缓存的历史往来有提示，可继续历史同步补齐。本轮不包含后续候选 A5 的会话 AI。

## A2：联系人补全

候选来自当前发件账户的本机历史收发邮件和草稿，包含发件人、To / Cc / Bcc 及 Reply-To。按出现频率、最近时间排序，可搜索显示名或邮箱；排除本账户、自身别名以及已经填入 To / Cc / Bcc 的地址，不从垃圾邮件或已删除邮件推荐，也不访问云通讯录。

选择候选只替换光标所在的地址片段，其他地址保留；显示名中的逗号和引号正确转义。建议随发件账户切换，保留普通文本编辑、键盘焦点和本机草稿保存。暂未增加独立通讯录管理或云端联系人同步。

## B1、B2：本机全文与条件搜索

正文、发件人和收件人、主题、分类、附件名称与提取文本、译文及 AI 结果进入 SQLite FTS5 索引。采用规范化的双字符 n-gram 候选匹配，再核对完整子串，覆盖中文两字词、长句中间的词和中英混排；单字符使用本机文本回退查询。索引为可重建的派生数据，不改变现有 `user_version=2`。数据库触发器记录邮件、附件和 AI 任务的变化，搜索时增量补齐，退出和重启不会丢失待更新项。

| 条件 | 示例 | 语义 |
| --- | --- | --- |
| 发件人 | `from:wang@example.com` | 匹配姓名或邮箱子串 |
| 收件人 | `to:finance@example.com` | 同时检查 To、Cc、Bcc |
| 抄送、主题、分类 | `cc:team subject:合同 category:审批` | 分别检查对应字段 |
| 日期 | `after:2026-10-01 before:2026-11-01` | 按本机日历日期，起始日包含、截止日不包含 |
| 状态 | `is:unread`、`is:read`、`is:starred` | 未读、已读或星标 |
| 附件 | `has:attachment` | 有附件 |
| 账户 | `account:me@example.com` | 按完整邮箱、唯一名称或 ID 指定账户 |
| 文件夹 | `folder:sent` | 支持 inbox、sent、archive、trash、drafts、spam 及中文名称 |

关键词和多个条件按“同时满足”组合，空格短语可使用英文双引号。例：`"采购合同" from:"王敏" after:2026-10-01 folder:inbox`。无效日期、未知条件、未闭合引号和不存在或重名的账户均给出说明。条件面板可选择全部账户；查询中的明确账户条件优先于侧栏账户。结果显示实际账户、文件夹及命中片段，打开、回复和移动仍使用原邮件身份，分页不重复或跳过结果。

条件面板的日期通过日历选择；日历面板宽 360 pt，年月无底色菜单居中，翻月按钮分列两侧，与日期网格对齐，减少两侧留白。支持上月、下月、年份与月份菜单，以及“今天”和“清除日期”。选择后回到同一条件面板，保留关键词、往来对象及其他条件；日期按本机时区计算，起始日包含、截止日不包含。

状态菜单包含全部状态、未读、已读、星标、已发送、草稿箱、已归档和已删除；后四项与文件夹选择同步，避免切换状态时留下冲突条件。选择未读、已读或星标后仍可叠加文件夹条件。

明确选择草稿箱（`folder:drafts`）时，检索当前本机未发送草稿的主题、正文、往来地址和附件内容，日期取最后更新时间；已发送记录不计入。结果保留原草稿身份，打开后可查看内容、附件并“继续编辑草稿”；普通邮件索引数量不包含这些草稿，尚未同步服务器草稿。

搜索只覆盖本机已缓存内容，未下载的历史范围有提示；全文索引不能代替历史同步。保存搜索、统一收件箱和后续服务端搜索不在本轮范围内。

## E1：完整备份与恢复

备份 ZIP 包含一致的 SQLite 快照、全部数据库登记的附件文件，以及记录路径、字节数、SHA-256 和数量的清单。邮件、草稿、设置、模型列表、自定义分类、AI 结果、任务、活动和待同步操作均随数据库保留。导出后重新读取并核对所有校验值，通过后才生成最终文件；缺失附件不会被静默跳过。

恢复先校验 ZIP 格式、路径、文件清单、数据库完整性、必要记录字段、附件关联及每个文件的校验值，确认窗口显示时间和记录数。最终恢复还会检查文件是否在选择后改变。同步、发送、AI 和其他写入期间拒绝恢复；恢复期间拒绝并发写入。先将当前数据保存为 `backups/before-restore-*.zip`，再准备附件并在事务中替换记录、重建索引，失败时回滚并清理临时文件，原数据及原附件保留。恢复前备份可通过同一入口再次恢复。

备份中的发送中草稿恢复为“结果待确认”，不自动重发；运行中的整理和附件批量任务恢复为暂停，单封 AI 任务恢复为失败，保留已有结果和待同步操作。恢复后需先核对账户和待同步更改再同步服务器。

钥匙串授权码和 API Key 不在备份中，也不会在恢复时覆盖；数据保存位置沿用当前设置。备份未加密。当前支持压缩文件不超过 512 MB、解压内容不超过 2 GB、数据库不超过 256 MB、单附件不超过 50 MB；超限会停止并说明，不会导出残缺备份。更大的数据集需在退出应用后备份整个数据目录。当前数据必须可读取且登记附件完整，才能生成恢复前的完整备份。

## 验证与边界

自动测试通过 **133 项后端测试、45 项 Swift 测试**，覆盖损坏与篡改备份、校验值正确但字段或附件关联无效的备份、路径穿越、缺失附件、恢复前失败、恢复前备份的再次恢复、草稿和任务状态、并发互斥、自定义分类实际 Responses 请求、引用链和跨账户隔离、联系人排序及片段替换、中文全文与增量更新、条件组合与分页、本机草稿检索及编辑身份，以及跨时区日期、闰年和月历排列。

原生验证使用独立 App 标识、钥匙串服务和两个演示账户，包含 11 封合成邮件、本机草稿及附件；AI 仅连接本机模拟服务。已检查分类新增、模型使用、确认与撤销、三封跨文件夹会话、逐封回复身份、联系人键盘填入与去重、中文及跨账户搜索、具体错误说明、备份文件面板、校验确认、恢复前备份保留和索引重建。没有使用真实邮件执行恢复或调用云端 AI。

补充检查完整状态菜单、草稿结果继续编辑、日历翻月及日期回填、清除与今天快捷操作，确认日期选择后关键词和其余条件保留；已发送、日期范围与关键词组合检索返回预期邮件。发布完整测试记录为 `artifacts/release-v0013/tests.log`；前期功能和原生检查位于 `artifacts/priority-ui/`。

测试日志为 `artifacts/priority-tests.log`，原生验证资料在 `artifacts/priority-ui/`；构建产物、备份及演示数据均被 Git 忽略。未验证十万封邮箱、最低系统版本及多设备性能；本轮不增加 Gmail / Outlook 专用接入或 OAuth，也不扩展 Roadmap 中其他 20 项候选。
